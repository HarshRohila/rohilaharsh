// Result type for type-safe error handling
type Result<T, E> =
  | { ok: true;  value: T }
  | { ok: false; error: E };

async function fetchUser(id: string): Promise<Result<User, ApiError>> {
  try {
    const res = await fetch(`/api/users/${id}`);
    return { ok: true, value: await res.json() };
  } catch (e) {
    return { ok: false, error: toApiError(e) };
  }
}

Forcing Error Handling in TypeScript: A Result Type Implementation

The Problem: Runtime Crashes

Ever found yourself debugging a production issue only to discover that your API call crashed at runtime? You're not alone. In TypeScript, developers often use Promises and forget to handle errors, leading to runtime crashes that could have been prevented at compile time.

Languages like Java have a built-in solution: checked exceptions. They force developers to handle potential errors before the code even compiles. But TypeScript doesn't have this — so we need to build our own safety net.

The Solution: Result Types

By wrapping our return values in a Result type, we can force callers to explicitly handle both success and error cases. The compiler becomes our safety net, catching unhandled errors before they ever reach production.
